# Woko v0.1.0 release notes

**Status:** Ready for controlled production deployment  
**Release type:** Initial internal release

## Summary

Woko v0.1.0 delivers the first complete operational release of Millennia World School's facilities work-order application. It supports the lifecycle from planning and assignment through execution, approval, evidence, completion, notification, and reporting.

## Included

### Work management

- Internal and vendor work-order creation
- Human-readable work-order numbering
- Multiple PICs, reviewer, and overseer participation
- Priority, condition, status, execution window, and due-date tracking
- Deadline grouping, search, all-work, and my-work views
- Bilingual Bahasa Indonesia and English experience

### Workflow and governance

- Role-aware internal and vendor workflow validation
- Structured vendor search and proposal submission
- Proposal approval, rejection, and revision flows
- Completion review and manager approval
- Required summaries, reasons, evidence, and waivers where applicable
- Optimistic concurrency using work-order versions
- Timeline discussions and immutable audit records

### Integrations

- Google Workspace sign-in with hosted-domain enforcement
- Administrator-controlled user activation
- Google Picker file selection
- Google Drive Shared Drive evidence storage
- Optional Gmail API notification delivery

### Operations

- In-app notifications and PostgreSQL-backed background jobs
- Jakarta-time reminder scheduling by default
- Work-order reports and operational breakdowns
- Administrator management for users, locations, and work settings
- PostgreSQL migrations and seed data
- Liveness and readiness endpoints
- Dockerfiles and production Docker Compose stack

## Deployment prerequisites

Before production rollout, operators must provide:

- A Linux host or compatible Docker environment with Docker Compose v2
- Persistent disk capacity for PostgreSQL and backups
- DNS and an HTTPS reverse proxy
- A production `.env` stored outside version control
- A Google OAuth web client with the production callback URI
- Google Drive and Picker APIs with appropriately restricted credentials
- A Shared Drive, project root folder, and authorized Drive service account
- Optional Gmail service account and domain-wide delegation when email is enabled
- A backup destination outside the Compose volume

See the [Docker deployment guide](../deployment/docker.md).

## Known limitations

- The release targets one organization and one configured Google Workspace domain.
- Docker Compose is a single-host deployment and does not provide automatic high availability.
- There is no vendor-facing account or portal.
- Offline PWA use does not include offline writes or synchronization.
- Email requires Google Workspace administration and is disabled unless explicitly configured.
- Drive behavior depends on Shared Drive membership and Workspace ownership policy.
- Reporting is operational and in-app; scheduled exports and advanced analytics are not included.
- Infrastructure monitoring, centralized logs, and automated off-host backups must be supplied by the deployment environment.

## Upgrade notes

This is the initial release, so there are no application upgrade steps from an earlier supported version. Existing pre-release databases should still be backed up before running the v0.1 migration container. Never manually mark migrations complete; investigate and resolve any failed migration before starting the API.
