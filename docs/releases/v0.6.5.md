# Woko v0.6.5

Woko v0.6.5 introduces role-scoped work-order visibility, simplifies the Work Orders navigation, and improves participant identification across work-order views.

## Access model

- Administrators and Facilities Managers can view every work order.
- Managers can switch between **All** and **My involvement** within the Work Orders page.
- PICs, workers, reviewers, and overseers only receive work orders where they are an assigned participant.
- Users with multiple roles receive the broadest allowed scope; a worker who is also a Facilities Manager retains manager visibility.
- Direct work-order detail requests apply the same visibility rule, preventing unrelated records from being opened by URL.
- Organization-wide reports remain available only to Administrators and Facilities Managers.

## Interface

- Replaced separate All Work Orders and My Work navigation destinations with one **Work Orders** destination.
- Added a compact manager-only **All / My involvement** scope control.
- Regular participants receive one non-redundant list containing only relevant work.
- Mobile navigation now adapts to the destinations authorized for the current user.
- Work-order cards and details show role-specific participant avatars and profile photos.
- Completed work orders default to the reopen action when further action is required.
- Local development now runs database migrations before starting the API, and the web app can recover from startup API errors.

## Upgrade notes

- Run migration `0015_worker_procurement_and_action_attachments.sql` before starting the API when upgrading from `v0.5.1`.
- No additional migration is required when upgrading from `v0.6.0` or `v0.6.1`.
- Validate role-scoped list, direct-detail, and report access with both manager and participant accounts.
