# Woko v0.6.0

Woko v0.6.0 adds restricted internal workers, internal procurement tracking, PIC work-order creation, action-bound attachment contexts, and participant-level Google Drive access synchronization.

## Highlights

- Added the global `WORKER` role and internal-only worker assignments.
- Assigned workers can view work, discuss progress, open Drive files, and record progress only while internal work is active and `IN_PROGRESS`.
- Workers cannot transition workflow, complete work, change condition, manage participants, or act on proposals.
- Administrators, Facilities Managers, and PICs can create work orders.
- Added internal procurement states: not required, proposal required, submitted, approved, rejected, and revision required.
- Internal work cannot move from `IN_PROGRESS` to `REVIEW` with unresolved procurement unless a manager records an override reason.
- Added a separate internal procurement review queue.
- Attachment records now include action context, status, and attachment time. Detail views show a read-only file list rather than generic evidence upload controls.
- Progress, vendor proposal, and procurement actions support local upload and Google Drive selection.
- Work-order Drive folders synchronize reader access for the creator and active participants and persist synchronization failures for operations review.

## Google Workspace checklist

- Confirm the Shared Drive permits direct folder sharing to users in the configured Workspace domain.
- The service account requires Drive API access to create folder permissions and manage files in the configured Shared Drive.
- Folder permission synchronization uses the `reader` role. Woko continues to perform file writes through the API identity.
- Workspace policy can prohibit direct folder sharing; Woko records those failures but cannot bypass administrator policy.
