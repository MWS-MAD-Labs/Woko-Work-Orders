# Woko v0.5.1 release notes

**Status:** Production release candidate  
**Release type:** Production deployment and operations milestone

## Summary

Woko v0.5.1 establishes the maintained production deployment on Komodo, enables signed GitHub Actions deployments, and prepares the production database and Google Workspace integrations for operational use.

The release tag and GitHub release should be created only after the final deployed commit passes the production checklist below.

## Included

### Deployment and operations

- Git-backed Komodo Stack deployment from `main`
- Protected Komodo variables for database and Google credentials
- File-based Docker secrets for Drive and Gmail service accounts
- Locally built API and web images with refreshed base images
- Health-gated PostgreSQL, migration, API, and web startup
- Cloudflare Tunnel ingress for `https://woko.mws.web.id`
- Signed GitHub Actions webhook triggering a Komodo force-deploy Procedure
- Automatic rebuild and migration on pushes to `main`

### Production configuration

- Google OAuth restricted to `millennia21.id`
- Production OAuth callback at `https://woko.mws.web.id/api/v1/auth/callback`
- Google Drive and Picker production configuration
- Gmail notification delivery using `no-reply@millennia21.id`
- Jakarta application time zone and background job processing
- PostgreSQL exposed only on host loopback

### Data preparation

- All migrations through `0014_user_preferred_locale.sql`
- Current development location configuration migrated into production
- One campus, five buildings, and 67 hierarchical location options
- Location UUIDs and parent-child relationships preserved

### Reliability fix

The migration container now mounts the same Drive and Gmail service-account secrets as the API container. This allows migrations to load production configuration when Gmail delivery is enabled.

## Upgrade and deployment notes

- Back up PostgreSQL before upgrading an existing environment.
- Do not delete the `woko_woko-postgres` volume during normal deployments.
- The migration service is expected to exit successfully with code `0`.
- Komodo should ignore `migrate` when evaluating long-running Stack health.
- `Run Build` must remain enabled because the API and web images are built from repository source.
- Automatic deployment uses the `Woko Production Redeploy` Komodo Procedure and `.github/workflows/deploy-komodo.yml`.

### Known dependency advisories

- `npm audit --omit=dev` reports high-severity advisories in `fast-uri` and transitive Sharp versions used by PWA asset-generation tooling.
- The runtime API uses Sharp `0.35.3`; the older Sharp versions are pulled by build-time PWA tooling.
- The remaining automatic audit remediation proposes a breaking dependency downgrade and is intentionally deferred for a dedicated compatibility update.
